# `robobench init` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `robobench init`, which scaffolds a commented starter `config.yaml` (active `robot`/`dds`, optional sections commented), so new users have a quick on-ramp instead of digging the campus example out of `examples/`.

**Architecture:** A pure `render_config_template()` in `config.py` returns the YAML text (placeholders, or values from optional flags); a thin `_cmd_init` CLI command writes it to `--output` (default `./config.yaml`), refusing to clobber an existing file unless `--force`. No network/SSH/rclpy — fully unit-testable.

**Tech Stack:** Python 3.11+, argparse, PyYAML (for the round-trip test), pytest, ruff. Tests/lint: `.venv/Scripts/python.exe -m pytest -q` / `.venv/Scripts/python.exe -m ruff check src tests`. Baseline: 207 passed, version 0.11.2a0.

Spec: `docs/superpowers/specs/2026-05-30-robobench-init-design.md`.

```python
def render_config_template(
    *,
    ip: str | None = None,
    ssh_user: str | None = None,
    ssh_pass: str | None = None,
    namespace: str | None = None,
    discovery_port: int = 11811,
) -> str:
    """Render a starter config.yaml as text (used by `robobench init`).

    The active ``robot`` and ``dds`` sections are filled from the given values
    (placeholders when omitted); optional sections are emitted commented-out as
    inline documentation. The result parses cleanly via ``load_adapter_config``.
    """
    ip = ip or "192.168.x.x"
    ssh_user = ssh_user or "ubuntu"
    ssh_pass = ssh_pass or "turtlebot4"
    namespace = namespace or "turtlebot468"
    return f"""\
# robobench config — generated by `robobench init`.
# Required: the robot block. Everything else is optional (defaults shown).

robot:
  ip: "{ip}"          # robot's IP on your LAN
  ssh_user: "{ssh_user}"
  ssh_pass: "{ssh_pass}"
  namespace: "{namespace}"  # robot's ROS namespace

dds:
  discovery_port: {discovery_port}      # FastDDS Discovery Server port

# --- optional sections (uncomment + edit as needed) ---

# workspace:
#   dir: "~/my_ros2_ws"          # required for `robobench bringup` (colcon build)

# build:
#   packages: ["my_nav_pkg"]     # default: ["campus_nav_llm"]

# launch:
#   package: "my_nav_pkg"        # default: "campus_nav_llm"
#   file: "bringup.launch.py"    # default: "navigation_mode.launch.py"

# health:
#   user_input_topic: "/my_cmd"  # default: "/user_input"

# known_poses:                   # named poses for `robobench bringup --pose NAME`
#   home: {{ x: 0.0, y: 0.0, theta: 0.0 }}
"""
```

(The `{{ ... }}` in the commented `known_poses` line renders as a literal `{ ... }` — an inline-flow YAML dict — because it's inside an f-string.)

```python
def _cmd_init(args: argparse.Namespace) -> int:
    target = Path(args.output)
    if target.exists() and not args.force:
        print(f"error: {target} already exists (use --force to overwrite)", file=sys.stderr)
        return 2
    target.write_text(
        render_config_template(
            ip=args.ip,
            ssh_user=args.ssh_user,
            ssh_pass=args.ssh_pass,
            namespace=args.namespace,
        ),
        encoding="utf-8",
    )
    print(f"wrote {target}")
    print(
        f"next: edit it, then `robobench check --robot turtlebot4 ...` "
        f"or `robobench dashboard --robot turtlebot4 --config {target}`"
    )
    return 0
```
